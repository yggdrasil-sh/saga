> **Beta:** Saga is ready for everyday use, but still young – keep regular backups; some features are explicitly
> experimental. The version number has no suffix; "Beta" is a label, not a separate update channel.

Saga 2.5 is the biggest chapter yet: calls run through a built-in node behind any reverse proxy with WebSocket
support – **one domain, port 443 only** – the new Tiptap editor works live with others, and chats can do a lot more.
The [Saga apps 2.5](https://github.com/yggdrasil-sh/saga-apps/releases) appear at the same time. Deutsch: see below.

## Highlights for self-hosters

- **One domain, port 443 only.** Behind a proxy that terminates TLS itself (e.g. Nginx Proxy Manager) all Saga needs
  is one name, port 443 and WebSocket pass-through ("Websockets Support"). No second name for the call node, no TLS
  pass-through, no extra ports. Optional: `SAGA_TLS=1` lets Saga accept HTTPS itself and share port 443 with the node
  ("one port" mode).
- **Calls and group calls through the built-in Gjallarhorn node** (experimental, off by default). The apps tunnel
  their media over a WebSocket to `/api/sfu/ws` on your normal Saga address; Chrome/Edge and Firefox use the new
  frame route over the same address. End-to-end encrypted – through the node, too.
- **All calls through the node.** With Gjallarhorn on, "All calls via nodes (also 1:1)" is on by default: 1:1 calls and
  groups of three or four run through the node, so devices never see each other's IP addresses. Direct connections
  remain only as a fallback (no node ready, or an active device of the other person cannot use it).
- **Calls that grow:** turn a 1:1 into a conference without dropping the call, bring people into a running group call
  (even from outside the chat), see who is "Not in the call" and ring them again, move a call to another of your
  devices and back.
- **Tiptap is the default editor.** Mentions of people with @, synced blocks, tables, code, math, columns and media.
  With the admin switch "Live co-editing" people see each other's typing and cursors instantly – also on pages shared
  from another Saga server, if both servers have it on.
- **Modern chats (level 3) are the default:** reactions, replies, editing, voice messages, formatting and @mentions;
  groups with admins, picture and description; contacts; pin, mute for a set time, mark as unread. Still end-to-end
  encrypted.
- **Pages and databases:** sub-pages appear inside their parent page (list or gallery), 36 Saga seals as page icons,
  a cover gallery with 100 pictures of the Saga elf, redesigned widgets and charts; databases get formulas, rollups,
  person and file properties, a timeline view and CSV export.
- **Easy to move in:** import from Notion, Trilium, Markdown/Obsidian and CSV.
- **API and MCP:** API tokens with scopes, public API `/api/v1`, webhooks and an MCP server (`/mcp`).
- **Federation:** live co-editing across servers, people from other servers in local groups, mentions and adding
  people to calls across servers.
- **For admins:** new "Diagnostics" page (error reports and "Send diagnostics" with an ID `D-…`, call and editor
  diagnostics) and a "Network" map of connected servers, nodes and clients. Security fixes after a second penetration
  test.

## Upgrading from 2.4 (or 2.3)

Full guide: [docs/UPGRADE-2.5.md](https://github.com/yggdrasil-sh/saga/blob/main/docs/UPGRADE-2.5.md) (German),
short English version [docs/en/UPGRADE-2.5.md](https://github.com/yggdrasil-sh/saga/blob/main/docs/en/UPGRADE-2.5.md).

1. **Back up** (`docker compose exec saga python run.py backup --dateien`, plus `.env`). Saga also makes its own
   backup before migrating.
2. **Update:** `docker compose pull && docker compose up -d`. With `SAGA_VERSION=2` (default) you get 2.5 automatically.
   The database migrates on start to schema **35**. From 2.3 you can go straight to 2.5.
3. **Minimum for the proxy:** one domain, port 443, **WebSocket upgrade passed through** (Nginx Proxy Manager:
   "Websockets Support" on; nginx: `Upgrade`/`Connection` headers; Traefik and Caddy: nothing to do). Without it
   `/api/sfu/ws` answers **426** and calls through the node do not connect. Admin → Calls → "Check now" tests it.
4. **Check the admin area:** Gjallarhorn stays off until you turn it on; "All calls via nodes" counts as on even if an
   older "off" was saved (switch it off deliberately if you want direct 1:1 calls); modern chats are on by default;
   the page editor switches to Tiptap once (Editor.js remains selectable); "Live co-editing" is off by default.
5. **Apps:** new features need apps 2.5. Older apps still sign in and keep working, with the limits listed in the guide.
6. **No downgrade:** after the migrations 2.4 no longer starts on this database. Going back means restoring the backup
   from before the update **with 2.5** and then switching `SAGA_VERSION` back (guide, section 7).

## Known limitations

- **Gjallarhorn is experimental** and off by default; tested with up to **4 people or devices per call**. Larger calls
  will follow after 2.5. Please report problems via Settings → Help → "Send diagnostics".
- **Safari** (and every browser on iPhone/iPad) does not call over the frame route yet: there, calls run directly or
  through a node with UDP or TURN-TLS – behind Nginx Proxy Manager without those routes, directly.
- **Older apps (2.4/2.3):** a 1:1 falls back to a direct call; group calls with 5 or more or through the tunnel need
  Saga 2.5; large non-video files in the new block format show "Open with a newer Saga version".
- **Live co-editing** is still marked as a test stage and off by default; across servers both servers need it on.
- The classic editor (Editor.js) will be removed in a later version.
- In "one port" mode (`SAGA_TLS=1`) HTTP/2 is off for now.
- Cloudflare (orange cloud) passes WebSockets through, but permanent media traffic may violate their terms – check them
  or use "DNS only".

## Deutsch

> **Beta:** Saga ist im Alltag nutzbar, aber noch jung – mach regelmäßig Backups; einige Funktionen (vor allem Anrufe
> über Gjallarhorn) sind ausdrücklich experimentell. Die Versionsnummer bleibt ohne Zusatz; „Beta“ ist eine Einordnung,
> kein eigener Update-Kanal.

Saga 2.5 ist das bisher größte Kapitel: Anrufe laufen über einen eingebauten Knoten hinter jedem Reverse Proxy mit
WebSocket – **eine Domain, nur Port 443** –, der neue Tiptap-Editor arbeitet live mit anderen, und Chats können viel
mehr. Gleichzeitig erscheinen die [Saga-Apps 2.5](https://github.com/yggdrasil-sh/saga-apps/releases).

### Höhepunkte für Selbsthoster

- **Eine Domain, nur Port 443.** Hinter einem Proxy, der TLS selbst beendet (z. B. Nginx Proxy Manager), braucht Saga
  nur einen Namen, Port 443 und durchgereichte WebSockets („Websockets Support“). Kein zweiter Name für den
  Anrufknoten, keine TLS-Durchreiche, keine weiteren Ports. Optional nimmt Saga mit `SAGA_TLS=1` HTTPS selbst an und
  teilt Port 443 mit dem Knoten (Betriebsart „Ein Port“).
- **Anrufe und Gruppenanrufe über den eingebauten Knoten Gjallarhorn** (experimentell, ab Werk aus). Die Apps tunneln
  ihre Medien per WebSocket an `/api/sfu/ws` der normalen Saga-Adresse, Chrome/Edge und Firefox nehmen den neuen
  Rahmen-Weg über dieselbe Adresse. Ende-zu-Ende-verschlüsselt – auch über den Knoten.
- **Alle Anrufe über den Knoten.** Mit Gjallarhorn ist „Alle Anrufe über Knoten (auch 1:1)“ ab Werk an: auch Anrufe zu
  zweit und Gruppen zu dritt oder viert laufen über den Knoten, die Geräte sehen keine IP-Adressen voneinander. Direkt
  verbindet Saga nur noch als Rückfall (kein Knoten bereit oder ein aktives Gerät des Gegenübers kann es nicht).
- **Anrufe, die mitwachsen:** aus einem 1:1 ohne Unterbrechung eine Konferenz machen, Personen in den laufenden
  Gruppenanruf holen (auch von außerhalb des Chats), „Nicht dabei“ mit „Erneut klingeln“, Anruf auf ein anderes eigenes
  Gerät übergeben und zurück.
- **Tiptap ist Standard-Editor.** @-Erwähnungen von Personen, synchronisierte Blöcke, Tabellen, Code, Mathe, Spalten
  und Medien. Mit dem Admin-Schalter „Gleichzeitig bearbeiten live“ sehen alle Eingaben und Cursor der anderen sofort –
  auch in Seiten, die ein anderer Saga-Server geteilt hat, wenn beide Server ihn an haben.
- **Moderne Chats (Stufe 3) sind Standard:** Reaktionen, Antworten, Bearbeiten, Sprachnachrichten, Formatierung und
  @-Erwähnungen; Gruppen mit Admins, Bild und Beschreibung; Kontakte; anheften, stummschalten mit Dauer, als ungelesen
  markieren. Weiter Ende-zu-Ende-verschlüsselt.
- **Seiten und Datenbanken:** Unterseiten erscheinen in der Elternseite (Liste oder Galerie), 36 Saga-Siegel als
  Seitensymbole, eine Titelbild-Galerie mit 100 Bildern der Saga-Elfe, neu gestaltete Widgets und Diagramme;
  Datenbanken bekommen Formeln, Rollups, Personen- und Datei-Eigenschaften, eine Zeitleiste und CSV-Export.
- **Leichter Umzug:** Import aus Notion, Trilium, Markdown/Obsidian und CSV.
- **API und MCP:** API-Tokens mit Bereichen, öffentliche API `/api/v1`, Webhooks und ein MCP-Server (`/mcp`).
- **Föderation:** live gemeinsam bearbeiten über Servergrenzen, Personen anderer Server in lokalen Gruppen,
  Erwähnungen und Personen in Anrufe holen über Servergrenzen.
- **Für Admins:** neue Seite „Diagnose“ (Fehlerberichte und „Diagnose senden“ mit Kennung `D-…`, Anruf- und
  Editor-Diagnose) und die Karte „Netz“ mit verbundenen Servern, Knoten und Clients. Sicherheitskorrekturen nach einem
  zweiten Pentest.

### Upgrade von 2.4 (oder 2.3)

Ausführlich: [docs/UPGRADE-2.5.md](https://github.com/yggdrasil-sh/saga/blob/main/docs/UPGRADE-2.5.md).

1. **Backup** (`docker compose exec saga python run.py backup --dateien`, dazu die `.env`). Saga legt vor dem Umbau
   zusätzlich selbst ein Backup an.
2. **Aktualisieren:** `docker compose pull && docker compose up -d`. Mit `SAGA_VERSION=2` (Standard) kommt 2.5 von
   selbst. Die Datenbank wird beim Start auf Schema **35** gehoben; von 2.3 geht es direkt auf 2.5.
3. **Mindestanforderung an den Proxy:** eine Domain, Port 443, **WebSocket-Upgrade durchreichen** (Nginx Proxy Manager:
   „Websockets Support“ an; nginx: Kopfzeilen `Upgrade`/`Connection`; Traefik und Caddy: nichts zu tun). Ohne das
   antwortet `/api/sfu/ws` mit **426**, Anrufe über den Knoten kommen nicht zustande. Prüfen: Admin → Anrufe →
   „Jetzt prüfen“.
4. **Admin-Bereich prüfen:** Gjallarhorn bleibt aus, bis du es einschaltest; „Alle Anrufe über Knoten“ gilt auch bei
   einem früher gespeicherten „aus“ als an (wer 1:1 direkt will, schaltet es bewusst aus); moderne Chats sind
   Standard an; der Seiten-Editor stellt einmalig auf Tiptap um (Editor.js bleibt wählbar); „Gleichzeitig bearbeiten
   live“ ist ab Werk aus.
5. **Apps:** Neues braucht die Apps 2.5. Ältere Apps melden sich weiter an und funktionieren, mit den in der Anleitung
   genannten Grenzen.
6. **Kein Downgrade:** Nach den Migrationen startet 2.4 auf dieser Datenbank nicht mehr. Zurück geht es nur, indem du das
   Backup von vor dem Update **mit 2.5** einspielst und danach `SAGA_VERSION` zurückstellst (Anleitung, Abschnitt 7).

### Bekannte Grenzen

- **Gjallarhorn ist experimentell** und ab Werk aus; getestet mit bis zu **4 Personen bzw. Geräten je Anruf**. Größere
  Anrufe kommen nach 2.5. Probleme bitte über Einstellungen → Hilfe → „Diagnose senden“ melden.
- **Safari** (und jeder Browser auf iPhone/iPad) telefoniert noch nicht über den Rahmen-Weg: dort direkt bzw. über einen
  Knoten mit UDP oder TURN-TLS – hinter Nginx Proxy Manager ohne diese Wege also direkt.
- **Ältere Apps (2.4/2.3):** Ein 1:1 läuft direkt; Gruppenanrufe ab 5 bzw. über den Tunnel brauchen Saga 2.5; große
  Dateien im neuen Blockformat (außer Videos) erscheinen als „Mit neuerer Saga-Version öffnen“.
- **Gleichzeitig bearbeiten live** ist noch als Teststufe gekennzeichnet und ab Werk aus; über Servergrenzen müssen beide
  Server es an haben.
- Der klassische Editor (Editor.js) wird in einer späteren Version entfernt.
- In der Betriebsart „Ein Port“ (`SAGA_TLS=1`) ist HTTP/2 vorerst aus.
- Cloudflare (orangene Wolke) reicht WebSocket durch, dauerhafter Medienverkehr kann aber gegen deren
  Nutzungsbedingungen verstoßen – prüfen oder „DNS only“.
